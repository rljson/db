# Commit

`gg can commit` checks all repos of the ticket in parallel, `gg do commit`
commits each repo only when its checks are green. The message also becomes the
`CHANGELOG.md` entry.

## 1. Use the ticket commands

Run `gg can commit` and `gg do commit` from the ticket folder. They act on
every repo of the ticket at once and do the work in parallel.

Never loop over the repos with `gg one can commit` or `gg one do commit`.
The loop checks one repo after the other and takes many times as long.

Use the `gg one` form only in a standalone repo that belongs to no ticket.

## 2. Propose a message

Look at `git status` and `git diff` in the repos of the ticket. Propose
for each repo an imperative one-liner that says what the step does in that
repo, not which files changed. Write it as `nextCommitMessage` into
`.gg/publish_config.json` of the repo, or update it there if it no longer
matches the diff (see the development guide). Let the user confirm them.

A dependency describes its change in its own terms. When a repo of the
ticket uses another one, the message of the dependency never names the
parent repo, the goal of the ticket or the use case of the parent — the
parent may name the dependency. The same holds for the `mergeMessage`.

- Wrong in `gg_git`: `Add remote creation for gg do create repo`
- Right in `gg_git`: `Add a function that creates a remote repository`
- Right in `gg`: `Create the remote repository with gg_git`

Section "Describe every repo in its own terms" of
`doc/en/guides/for-ai/ai-dev-guide.md` has the details.

Check in the same pass whether the diff changes what the `index.jsonc` of
the repo says — its `summary`, `domain` or `interfaces` — and update it
before committing. If the repo has no `index.jsonc`, create it now from
`doc/en/templates/index-template.jsonc`, whatever the diff. Section "Keep the
index.jsonc up to date" of `doc/en/guides/for-ai/ai-dev-guide.md` has the
details.

## 3. Commit

From the ticket folder, check all repos at once, then commit them:

```bash
gg can commit
gg do commit --no-interactive
```

`gg can commit` records the result of every repo, so `gg do commit` only
confirms it and does not run the checks again.

`--no-interactive` commits every repo with its own `nextCommitMessage` and
asks nothing. Repos without one get the ticket description.

Use `-m"<message>"` only when every repo of the ticket shall get the same
message and no repo of the ticket depends on another. Add `-l` when the
message must not land in `CHANGELOG.md`.

## 4. On a failing check

`gg can commit` stops at the first red repo. Fix the cause, never the
check, then run `gg can commit` again for the whole ticket — the repos
that passed before only confirm their result. Files generated by the DNA are committed separately as
`#gg: generated DNA` — never edit an instance by hand, change its source
under `dna/` instead.

## Important

- Never commit without the confirmed messages.
- Never commit the repos of a ticket one by one with `gg one`.
- Never let a parent repo leak into the message of its dependency.
- Never push here — that is `/gg-push`.
